# 할아버지 선물 선택 퍼즐 — 설계

**날짜** 2026-08-07
**범위** ITM-12 편의점 선물 5종 선택 · 오답 엔딩 · 효자손 강탈 추격 개편 · 바닥 양갱 힌트
**선행** PR #8 (items.glb 반입) — 메시 5종은 이미 게임에 들어와 있다

---

## 1. 배경

`assets/items.glb`에 편의점 선물 후보 5종 메시가 들어왔으나 게임 로직이 없다.
`data/items.ts`의 `I-12`는 아직 `name: '붕어빵'`, `node: 'ITM12_Fishbread'`를 가리키고,
그 노드는 **어느 GLB에도 없다**. `I-12`가 `PLACEHOLDER_ITEMS`에 있어 에러 없이 갈색
자리표시자 상자로 렌더되어 왔다.

문서상 설계(`docs/OBJECT-MANIFEST.md:166`, `docs/GDD-subway-rush.md:264`)는
"후보 5종 중 하나를 Z2 편의점에서 고르고 정답은 양갱"이다. 이 스펙은 그것을 구현한다.

### 확정된 디렉터 결정

| 쟁점 | 결정 |
|---|---|
| 붕어빵 | **부활시키지 않는다.** 메시가 폐기됐고(`GDD:21`) 정답은 양갱 하나 |
| 5종 데이터 | **아이템 5개로 분리** (변형 필드 방식 기각) |
| 선택 UI | 매대 1회 상호작용 → **5지 선택창** |
| 구매 개수 | **딱 하나만** |
| 오답 구매 후 | **되돌리기 없음** |
| 피격 | **2대째 즉사** (1대는 "딱!" + 감속) |
| 추격 지속 | 30초 → **10초** |

## 2. 데이터

### 2.1 아이템

`I-12`를 양갱으로 재정의하고 오답 4종을 추가한다.

| ID | 이름 | 노드 | `negates` | 역할 |
|---|---|---|---|---|
| `I-12` | 양갱 | `ITM12_Yanggaeng` | `['OBS-14']` | **정답** |
| `I-15` | 바나나우유 | `ITM12_BananaMilk` | `[]` | 헷갈리는 오답 |
| `I-16` | 초콜릿 | `ITM12_Chocolate` | `[]` | 헷갈리는 오답 |
| `I-17` | 탄산음료 | `ITM12_Soda` | `[]` | 명확한 오답 |
| `I-18` | 새우깡 | `ITM12_SnackBag` | `[]` | 명확한 오답 |

전부 `slot: true`, `consumable: true`, **`use: 'use'`** — 현재 `I-12`와 같다.
`'key'`가 아니다. `'key'`는 효자손처럼 "쓰는 물건이 아니라 상호작용의 조건"에 붙는다
(`items.ts` I-01 주석). 선물은 실제로 건네는 물건이므로 `'use'`다.

**`I-15`는 이미 `ItemId` 유니온에 있으나 정의가 없는 예약 자리다**(`state/types.ts:23`).
이번에 정의를 채운다. 유니온에는 `I-16`·`I-17`·`I-18`만 추가한다.

`I-12`를 `render/props.ts`의 `PLACEHOLDER_ITEMS`와 `PLACEHOLDER_LOOK`에서 **뺀다** —
이제 진짜 메시가 있다. 오답 4종은 자리표시자에 넣지 않는다(전부 메시가 있다).

`OBS-14.counteredBy`는 `['I-12']` 그대로 둔다. 오답으로는 추격이 막히지 않아야 하므로
오답 4종의 `negates`는 비운다. `tests/unit/obstacles.test.ts:131`의 양방향 유닛이
그대로 통과한다.

### 2.2 엔딩

`ENDINGS` 14종 → 16종.

| ID | 이름 | 트리거 |
|---|---|---|
| `E-15` | 이걸 누가 먹어 | 오답 증정 |
| `E-16` | 딱! | 단소 2대째 |

지시는 엔딩 하나였으나 **오답과 피격은 화면 문구가 완전히 다르다.** 하나로 합치면
어느 쪽으로 끝났는지 플레이어가 모른다. 디렉터 승인 완료.

둘 다 `when: () => false`로 둔다. `resolveEnding`은 열차 출발 경로에서만 쓰이고
(`systems/tick.ts:124-128`), 이 둘은 `END` 액션으로 id를 직접 넘겨 강제한다.
`when`이 참이 될 수 있으면 열차 출발 시 오검출된다.

`ui/collection.ts:75`가 `ENDINGS.length`를 세므로 도감 분모가 14 → 16이 된다.
기존 세이브의 `seenCount`는 본 것만 세므로 영향 없다.

## 3. 매대 — `OBJ-19-GIFT`

편의점 파사드 `OBJ-19-CVS`는 `y = 25.7`이고, 슬랩(Z2-NE)은 `y = 25.4`에서 시작한다.
기존 `OBJ-19-MASK`가 `x: 24.0, y: 25.55`에 같은 규칙으로 놓여 있다.
`OBJ-19-GIFT`는 **`x: 26.0, y: 25.55, z: FLOOR.B1`** — 마스크에서 동쪽으로 2m.

`kind: 'talk'` (선택 UI를 여는 종류, 그 자체는 0초).

### 선택창

`grandpaBranches`와 같은 `Branch` 패턴을 5지로 확장한다.
`key` 타입이 `1 | 2 | 3`이므로 `1 | 2 | 3 | 4 | 5`로 넓힌다 — `dialogPick`과
`ui/dialog.ts` 양쪽이 같이 넓어져야 한다.

```
giftBranches(s) → [
  { key: 1, label: '양갱',       enabled: !bought, note: '' },
  { key: 2, label: '바나나우유',  enabled: !bought, note: '' },
  { key: 3, label: '초콜릿',     enabled: !bought, note: '' },
  { key: 4, label: '탄산음료',    enabled: !bought, note: '' },
  { key: 5, label: '새우깡',     enabled: !bought, note: '' },
]
```

`bought = s.flags.includes('GIFT_BOUGHT')`. 구매 후 전 분기 `enabled: false`,
note는 `'이미 골랐다'`.

구매 시 발행할 액션: `PICKUP` → `FLAG GIFT_BOUGHT on` → 토스트.

**note를 다섯 개 모두 비운다.** 다른 분기(`'+1.5s'`, `'+15s'`)는 note로 비용·이득을
알려주지만 여기서는 **note가 정답 힌트가 되어 버린다.** 값이 서로 다르면 "비싼 게 정답"
"시간이 더 드는 게 정답" 같은 잘못된 추론이 생기고, 힌트는 바닥 양갱(§6)이 져야 한다.

이 스펙은 **경제를 건드리지 않는다** — 가격도 잔액 차감도 넣지 않는다.
`kind: 'buy'`가 이미 "잔액 미차감"(`data/interactables.ts:20`)이므로 가격을 표시하면
차감되지 않는 값을 보여주는 셈이 되어 거짓말이 된다. 선물 가격 도입은 별도 작업.

## 4. 증정 — `grandpaBranches` key 2

```
label    '붕어빵을 드린다'  →  '선물을 드린다'
enabled  hasItem(s,'I-12')  →  GIFT_ITEMS.some((i) => hasItem(s, i))
note     '붕어빵이 필요하다' →  '선물이 없다'
```

`GIFT_ITEMS = ['I-12','I-15','I-16','I-17','I-18']`.

구매가 1회 한정이므로 **소지한 선물은 항상 최대 하나**다. 어느 것을 드릴지 다시 고를
필요가 없다.

- 소지품이 `I-12`(양갱) → 기존 경로 그대로. 효자손 획득, +1.5s
- 그 외 4종 → `{ t: 'END', endingId: 'E-15' }`

## 5. 추격 개편 — `systems/chase.ts`

### 튜닝 (`data/tuning.ts` `CHASE`)

```
durationMs   30_000 → 10_000
seizeHits    삭제
seizeMs      삭제
```

`speed: 5.0`(플레이어 걷기와 동일)과 `hitRangeM: 1.2`는 그대로 둔다.
스프린트 8.3 · 스태미너 100/초당 22 ≈ 4.5초면 37m를 달리고, 벤치(x=42)에서
안전지대(x=56)까지는 14m다 — 즉사로 바꿔도 도망이 성립한다.

### 로직

- `seize` 페이즈를 **삭제**한다. 효자손 회수 개념이 사라진다
- `hitCount >= 2` → `{ t: 'END', endingId: 'E-16' }`
- 1대째는 현행 유지 — `CHASE_HIT` · 화면 흔들림 · `'딱!  "이놈아!"'` · 감속 0.2
- 타임아웃 문구: `'할아버지가 숨이 찼다'` → `'늙었더니 몸이 내맘 같지 않구먼'`
- Z3 진입 해제(`safeX`)는 그대로

`CHASE_DONE`은 남는다 — 재발동 금지와 `interact.ts:310`의 "이번엔 꽉 쥐고 있다"
분기가 계속 동작해야 한다.

### 설계 변화 명시

`chase.ts:4-6`은 이 시스템을 "8초 아끼려고 훔쳤는데 감속 때문에 20초를 잃는다 →
도덕이 아니라 **산수로 손해**"로 설명한다. 2대째 즉사는 이 성격을 **"도박"으로 바꾼다.**
주석을 새 의도에 맞게 다시 쓴다 — 옛 주석을 남기면 다음 사람이 코드를 오해한다.

톤 가드레일(피 없음 · 데미지 수치 없음 · 슬랩스틱 · "딱!" 목탁음)은 유지한다.

## 6. 힌트 — 바닥 양갱

벤치(`42, 14.9`) 주변에 **3개**를 흩어 둔다. 하나만 두면 우연으로 읽히고,
문구의 "포장이 여럿"이 화면과 어긋난다.

배치는 벤치 남쪽 통행 구역, 서로 0.6m 이상 떨어뜨린다. 정확한 좌표는 구현 중
씬 실측으로 확정한다(벤치 솔리드 `ACT-02-BENCH` = rect[40.8, 14.6, 43.2, 15.4]와
겹치면 안 된다).

### 새 `InteractKind` — `'inspect'`

```
'inspect'   // 살펴본다 0.8s · 이동 가능 · 획득 없음
```

기존 `'aside'`는 "저기요" 3.0초라 의미가 맞지 않는다. `durationOf`에 0.8s를 넣고
`CANCEL_ON_MOVE`에는 **넣지 않는다**(`pickup`과 같은 취급).

문구:

> 누군가가 먹고 바닥에 버려놨다. 포장이 여럿인 걸 보면 누군가의 최애 간식인 모양이다.

`gives` 없음 — 획득되지 않는다. `once: false`로 두어 몇 번이고 다시 볼 수 있게 한다.

렌더는 `ITM12_Yanggaeng` 노드를 재사용하되 바닥에 눕힌다.
