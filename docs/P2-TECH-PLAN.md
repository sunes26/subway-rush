## 1. 기술 스택 — 바꾸지 않는다

| 층 | 선택 | P2에서 바뀌는가 |
|---|---|---|
| 언어 | TypeScript strict | — |
| 번들 | Vite 7 | — |
| 렌더 | Three.js 0.180 (툰 셰이딩) | — |
| 시뮬 | 순수 함수 + 단일 리듀서 | — |
| 오디오 | WebAudio 절차 생성 (에셋 0바이트) | 확장만 |
| 영속 | — | **`localStorage` 신설** ★ |
| 테스트 | Vitest(유닛) + Playwright(E2E) | — |
| 에셋 | Blender → glTF | 신규 메시 없음 (글리프) |

**새 의존성을 하나도 안 넣는다.** P2가 요구하는 것 중 라이브러리가 필요한 것은
`localStorage` 래퍼 하나뿐이고 그건 30줄이다. 번들 예산(gzip 900KB)이 이유고,
더 큰 이유는 **헤드리스 시뮬이 브라우저 API에 물들면 안 된다**는 것이다.

**규칙 3개를 유지한다** (P1에서 값을 지불하고 배운 것들):

1. **시스템은 `(GameState, ctx) => Action[]`** — 렌더를 모른다. 그래서 스윕이 돈다
2. **좌표는 `data/world.ts` 에서만 나온다** — 상호작용 테이블이 좌표를 새로 만들지 않는다
3. **타이머 감산은 `ADVANCE` 한 곳** — 시스템이 자기 타이머를 줄이면 프레임당 두 번 준다

## 3. 핵심 기능 작동 방식

### 3.1 시드 활성화 (`data/obstacles.ts`)

```
seed ──► splitmix32 ──► 파생 스트림 4개
          │
          ├─ 잔액 (기존)
          ├─ 게이트 (기존)
          ├─ ★ 방해요소 선택   shuffle(POOL_8).slice(0,4) → 비용합 ≤45s 될 때까지 재시도(최대 8회)
          └─ ★ 대기줄 길이     [ⓐⓑⓒ] 각 3~11명, 합계 21 고정
```

**파생 스트림을 나누는 이유**: 하나의 스트림을 순서대로 쓰면 *앞의 소비량이 바뀔 때
뒤가 전부 바뀐다.* P1에서 자판기 동전 분배를 넣자 게이트 시드가 통째로 바뀌어
회귀 테스트 6건이 한꺼번에 빨간불이 됐다. → 용도별로 `seed ^ SALT_x` 로 독립 스트림을 만든다.

**재시도 상한 8회**는 무한 루프 방지다. 8회 안에 못 찾으면 비용 낮은 순 4종을 그냥 쓴다
(도달 불가가 아니라 **덜 재밌는** 결과라 게임이 멈추지 않는다).

### 3.2 방해요소 판정 (`systems/obstacles.ts`)

전부 **같은 모양**으로 짠다 — 이게 6종을 6일이 아니라 하루에 짜는 방법이다.

```ts
type ObstacleRule = Readonly<{
  id: ObsId
  zone: ZoneId
  /** 발동 조건 — 순수. 상태만 본다 */
  fires: (s: GameState) => boolean
  /** 무효화 아이템 (소지 or 착용) */
  counteredBy?: readonly ItemId[]
  /** 발동 시 액션 */
  effect: (s: GameState) => readonly Action[]
  /** 재발동 쿨다운(ms) */
  cooldownMs: number
}>
```

`obstacleSystem` 은 활성 목록만 순회한다. **표 하나에 6줄 추가하면 방해요소 하나가 는다.**

| OBS | fires | counteredBy | effect |
|---|---|---|---|
| 05 물청소 | 구역 AABB 진입 && 스프린트 중 | I-08 | 미끄럼 stall 1.2s + 슬롯 랜덤 1개 드랍 |
| 06 전단지 | 반경 2.5m && 미착용 | I-05 | `TIME_PENALTY -5s` + stall 3.0s |
| 07 아주머니 | 반경 3.0m && 미착용 | I-05 | `TIME_PENALTY -15s` + 대화 강제 |
| 08 좀비폰족 | 이동체 AABB 겹침 | I-14(소모) | stall 0.6s + `TIME_PENALTY -4s` |
| 10 공사 | 오경로 AABB 진입 | I-13 | `TIME_PENALTY -20s` + 되돌림 |
| 13 역무원 | 시야콘 && 무단통과 플래그 | — | `END E-09` |

**stall 은 새 개념이 아니다.** `surge.stallMs` 가 이미 있고 같은 의미다 →
`player.stallMs` 로 승격해 역류·물청소·좀비폰족이 **한 필드를 공유**한다.
(따로 만들면 두 개가 동시에 켜졌을 때 어느 쪽이 이기는지가 미정의가 된다.)

### 3.3 아이템 효과 테이블 (`data/items.ts`)

P1의 `ItemDef` 에 필드 하나를 더한다.

```ts
effect?: Readonly<{
  kind: 'wear' | 'consume' | 'key'
  /** 무효화하는 방해요소 */
  negates?: readonly ObsId[]
  /** 즉시 효과 */
  onUse?: (s: GameState) => readonly Action[]
}>
```

**`negates` 를 아이템 쪽에도 두고 방해요소 쪽에도 둔다** — 중복이다. 의도적이다:
방해요소를 짤 때 "뭐로 막지"를 보고, 아이템을 짤 때 "어디 쓰지"를 본다.
정합성은 **유닛 테스트가 강제**한다(양쪽 표를 대조해 불일치면 실패).

### 3.4 역무원 (`systems/staff.ts`)

P1의 `chase.ts` 를 그대로 베낀다 — 순찰 경로 위를 왕복하고, `facing` 이 있고,
시야는 **각도 + 거리**로 판정한다(레이캐스트 금지 규칙 유지).

```
        시야콘: 반각 35° · 거리 8m · 눈높이 무시(2D)
        순찰: Z3 개찰구 뒤 x[63,72] 왕복, 주기 14s
        반응: fareEvaded 플래그가 켜진 채 시야 안 → 0.8s 유예 후 E-09
```

**0.8초 유예**가 있는 이유: 즉발이면 화면에 아무것도 안 보이고 끝난다.
유예 동안 호루라기가 울리고 화면 가장자리가 붉어진다 — **보이는 즉사**로 만든다.

### 3.5 비상게이트 (`systems/emergency.ts`)

상태 3개면 끝난다: `open: boolean` · `openedBy: 'wallet'|'interphone'|null` · `fareEvaded: boolean`.
개찰구 통과 판정(`gates.ts`)에 **분기 하나**를 더한다 — 비상게이트 x범위를 지나면
`GATE_PASSED` 를 내되 요금을 안 깎고 `fareEvaded` 를 켠다.

### 3.6 엔딩 (`data/endings.ts`)

배열에 8개 추가. **`when` 은 여전히 순수 함수 하나**다.
E-05만 복합식이고, 그래서 **결정 요인 리포터**를 같이 넣는다:

```ts
reason?: (s: GameState) => string   // "잔여 62s · 양심 +4 · 아이템 5종 · 무피격"
```

`BY_PRIORITY` 정렬은 모듈 로드 시 1회 유지(엔딩 화면이 매 프레임 부른다).

### 3.7 세이브 (`core/save.ts`)

```ts
export const loadSave = (): SaveData      // 실패 → 빈 세이브
export const recordEnding = (id, ms): void // 실패 → 메모리 격하, 조용히
```

**시뮬은 이 모듈을 임포트하지 않는다.** `main.ts` 와 `ui/collection.ts` 만 쓴다.
그래야 `tick()` 이 순수하게 남고 스윕이 노드에서 돈다.

### 3.8 오디오 (`audio/sfx.ts` · `ambience.ts`)

기존 `blip`/`noise` 두 헬퍼로 6종을 전부 만든다. 마스터 게인에 `muted` 스위치를 단다.
앰비언스만 별도 모듈 — **지속음이라 수명 관리가 다르다**(BufferSource 루프 + 크로스페이드).

### 3.9 tick 삽입 순서 (갱신)

```
ADVANCE → train파생 → rebuildDynamics
  → movement
  → chase          (이동 뒤: 8cm 지연 방지)
  → ★ staff        (chase 와 같은 이유 · 같은 자리)
  → crowd          (MOVE 재발행)
  → ★ obstacles    (crowd 뒤: 밀려난 최종 위치에서 구역 판정)
  → interact → qte
  → gates → gateKnockback
  → ★ emergency    (gates 뒤: 통과 판정을 덮어쓰지 않기 위해)
  → train
  → zone → 종료판정
```

**`obstacles` 가 `crowd` 뒤인 이유**: 인파에 밀려 물청소 구역에 들어가는 일이 있다.
앞에 두면 밀리기 전 위치로 판정해 *"분명 밟았는데 안 미끄러졌다"* 가 된다.
**`emergency` 가 `gates` 뒤인 이유**: 같은 틱에 둘 다 `GATE_PASSED` 를 내면
나중 것이 이긴다 — 요금 차감 여부가 뒤바뀐다.

### 어긋난 것 일곱

**1. 교체 모달을 "기다리는 창"으로 만들면 P1이 뒤집힌다.**
계획은 *"모달을 띄우고 0.9초 안에 못 고르면 P1 규칙으로 격하"* 였다. 그렇게 짜면
무입력 플레이가 **습득 지점마다 0.9초씩 멈춘다** — 헤드리스 스윕·자동조종이 그만큼 느려지고
P1 회귀 2건이 깨진다. → **P1 동작을 먼저 실행하고 0.9초 되돌림 창**으로 뒤집었다.
아무것도 안 누르면 P1과 완전히 같은 결과다.

**2. 동전이 프레임마다 잔액을 올렸다 (17,650원).**
`complete()` 의 습득 분기가 `PICKUP` 을 내고, `PICKUP` 리듀서가 `act` 의 busy 를 비우고 있었다.
동전은 `PICKUP` 을 안 내므로(잔액 직행) **busyId 가 안 지워져 매 프레임 완료**했다.
→ 완료 뒤 `ACT_CANCEL` 을 꼬리에 붙인다. **P1의 `aside` 도 같은 버그였다** —
토스트만 반복해서 증상이 안 보였을 뿐이다.

**3. 일렬로 선 대상은 각도 최소가 뒤집힌다.**
인파벽을 3인으로 복원하자 "눈앞 사람을 보고 `E` 를 눌렀는데 세 번째가 비켜서는" 일이 났다.
플레이어가 축에서 **12cm** 만 어긋나면 먼 사람의 각도가 더 작다(5.7° 대 2.9°).
→ 8° 안에서는 **가까운 쪽**이 이긴다(`INTERACT.aimTieRad`). 각도 우선 원칙은 유지.

**4. 즉사가 집계에 가려졌다.**
E-11(78)·E-09(75)를 E-10 양심 파산(80) 아래에 뒀더니 **그 자리에서 끝난 판을 나중 집계가
덮었다.** 우산으로 참사를 냈는데 화면에는 "양심 파산"이 떴다. → 즉사 2종을 84·83으로 올렸다.

**5. `items.glb` 의 노선도 노드 이름이 달랐다.**
`ITM13_Map` 으로 썼는데 실제로는 `ITM13_RouteMap` 이다. 콘솔 에러 1건으로 드러났고,
그 김에 **의도된 부재**(P2 신규 7종은 메시가 없다)를 자리표시자로 그리게 바꿨다 —
없는 노드를 조용히 넘기면 화면에 아무것도 안 서고, `console.error` 를 내면 E2E 의
"콘솔 에러 0건" 이 깨진다. 목록 밖의 노드 부재는 **여전히 에러**다(에셋 사고 감지선).

**6. 소프트웨어 래스터에서는 시뮬 시간이 실시간의 1/5 이하로 흐른다.**
E2E 에서 `waitForTimeout(900)` 으로 0.9초 창을 기다렸더니 창이 아직 안 열려 있었다.
실측 **벽시계 1.6초에 시뮬 0.2초** — 프레임이 길어 `MAX_STEPS_PER_FRAME`(5) 이 자른다.
→ P2 E2E 는 시간이 아니라 **상태**를 기다린다(`waitForFunction`).

**7. "넓은 곳"을 대합실로 잡으면 이동 측정이 벽에 잘린다.**
3초 직진이 15m 가 아니라 **10.96m** 로 나왔다 — 기둥 8본과 상가 때문이다.
→ 이동·마찰 측정은 Z4 운임구역 통로(x 72~95.8, 직선 21m)에서 한다.

**8. 프롭 20개가 드로우 콜 감지선을 넘겼다.**
습득물이 4종 → 20개(아이템 14 + 동전 6)가 되자 Z2 핫스팟이 **240콜**(선 235)이 됐다.
프러스텀 컬링으로는 안 줄어든다 — 이것들은 실제로 화면 안에 있다. → **거리 컬링**을 넣었다
(동전 12m · 나머지 26m). 240 → **236**. 상호작용 사거리 3m 의 8배 이상이라
*보이는 것과 잡히는 것*이 갈라지지 않는다. 남은 폭은 선을 **245** 로 올려 받았다 —
더 조이면 그 경계가 깨지기 시작하는 지점이었다.

**9. 촬영 spec 이 다시 타임아웃했다.**
`report.spec` 이 파일 하나로 9분을 먹고 540초에서 끊겼다. **단독 실행은 통과하는데
전체 실행에서만 죽으면 그게 타임아웃 신호다**(P1 에 같은 기록이 있다). → 900초로 올렸다.

### 플레이 확인에서 나온 것 둘 (E2E·유닛이 못 잡은 층)

**10. "할아버지가 뒤로 돈 채 쫓아온다."**
원인이 둘이었다. ① `CHASE_START` 가 `facing` 을 안 실어서 **발도 0.6초 동안 초기값 0(동쪽)**이
남았다 — 훔친 직후 눈앞에서 벌어지는 구간이다. ② `draw`·`swing` 이 아무 액션도 안 내
그 사이 `facing` 이 **얼어붙었다**. 스윙 중에 옆으로 돌면 허공을 보고 때렸다.
→ 시작 시 플레이어 방향을 싣고, 제자리 구간도 `CHASE_MOVE` 로 시선만 갱신한다.
**움직이지 않는 것과 안 보는 것은 다르다.** 유닛 3건으로 잠갔다.

> 렌더 쪽은 무죄였다 — 어깨축·머리기울기 두 지표로 앉음/추격 자세를 다 재 봤고
> `YAW_FIX.gp = π` 는 두 자세 모두에서 맞았다. 시뮬이 낸 값이 틀렸던 것이다.

**11. "사운드 추가한 거 맞아? 소리가 안 나는데."**
절차 생성음은 **울리고 있었다.** 마스터 0.22 × 발소리 게인 0.16 = 진폭 **0.035** —
P1 개찰구 삑(0.165)의 1/5 이라 사실상 안 들렸다. 상시음을 낮게 잡은 것이 화근이었다.
→ 마스터 0.22 → **0.34**, 상시음 게인 2~3배, 사건음은 균형만큼 낮춤.
**앰비언스는 진짜 무음이었다** — 자기 `AudioContext` 를 새로 만들어 제스처 밖에서
`suspended` 로 멈춘 채 깨어난 적이 없다. → `sfx` 의 살아 있는 컨텍스트와 마스터 버스를
**빌려 쓴다**(음소거도 한 스위치로 끝난다).

**12. 발소리는 결국 녹음 샘플로 갔다** (디렉터 지정 · `public/audio/footsteps.mp3` 80KB).
**에셋 0바이트 방침의 유일한 예외**다. 노이즈 버스트 한 방은 "툭"이지 발소리가 아니다 —
걸음은 뒤꿈치·발볼 두 접촉과 옷 소리가 겹친 복합음이라 사인파로 만들면 코드가 더 길어진다.
소스가 **단발이 아니라 연속 보행 루프**(5.04s)라 트리거가 아니라 **게이팅**으로 튼다:
이동 중에만 게인을 열고, 뛰면 `playbackRate` 1.32, 지하는 저역 통과로 눌러 실내를 만든다.
디코드 실패 시 절차 생성 발소리로 **폴백**한다.

**13. 방해요소에 몸이 없었다.**
*"도 아십니까 아주머니가 구현 안 된 것 같다"* — 맞다. 판정(`systems/obstacles.ts`)만 돌고
**화면에 아무도 없었다.** 원인은 코드가 아니라 반입이다: `aj`(PR_Book) · `ajp`(PR_Flyer) ·
`zp`(PR_Phone) · `ss`(경봉·테이저) 네 리그가 **목적별 클립까지 갖춘 채** `assets/` 에 있었는데
`tools/copy-assets.mjs` 목록에 없어 `game/public/` 로 안 넘어왔다.
→ 반입 목록에 넣고 `render/actors.ts` 가 그린다. 보이지 않는 방해요소는 GDD §11 이 금지한
**단서 없는 랜덤 처형**이다 — 피할 대상이 화면에 있어야 피한다.

규칙 하나를 같이 못 박았다: **이번 판에 안 켜진 방해요소는 몸도 없다.**
세계가 활성 목록에 대해 거짓말하면 시드 셔플이 의미를 잃는다(E2E 가 잠근다).
컬링은 26 m — 아주머니 반경(3 m)의 8배 이상이라 *보이는 것과 잡히는 것*이 안 갈린다.

**14. 인파벽은 판정만 3인이고 몸은 1인이었다.**
S20 에서 3인으로 복원했는데 렌더는 `cp` 하나만 그리고 있었다 — 안 보이는 벽 둘이 생긴다.
→ 같은 리그를 세 번 로드해 각자 배치한다(`loadNpcRig` 이 스켈레톤까지 복제한다).

**15. 추격 끼임 탈출이 뒤로 걸었다.**
*"할아버지가 뒤로 이동한다."* 원인은 `unstuckBackM` 후퇴다 — `facing` 은 플레이어를 향한 채
몸만 반대로 1.5 m 간다. 텔레포트를 피한 것까진 옳았지만 **얼굴은 앞, 몸은 뒤**가 됐다.
→ **옆으로 돈다.** 좌·우 90° 를 둘 다 시도해 더 멀리 가는 쪽을 쓰고, 둘 다 막히면 그때만
후퇴하되 **가는 쪽을 본다.** 기둥에 걸린 사람은 뒤로 걷지 않는다.

**16. 새 유닛 넷이 전부 거꾸로 걸었다 — 전방축은 리그마다 다르다.**
반입한 4종에 GP 를 보고 `π` 를 일괄로 줬다. 틀렸다. **배치가 둘로 갈린다:**

| 리그 | 보정 | 확인 |
|---|---|---|
| MC · CP | 0 | 조작 · 머리기울기 |
| GP · **AJ · AJP** | **π** | 0 이면 파마머리 뒤통수만 보인다 |
| **ZP · SS** | **0** | π 면 제복 단추·폰 화면이 안 보인다 |

⚠ **어깨축 카이럴리티로는 못 가른다.** MC(−1)와 CP(+1)가 **둘 다 정답인데 부호가 다르다** —
리그마다 미러링 여부가 달라서다. 서 있는 자세에서는 머리기울기도 0 에 가까워 무의미했다.
확실했던 유일한 방법은 **진행 방향 정면에서 근접 촬영**해 얼굴·단추·프롭이 보이는지 보는 것이다
(SS 제복 앞단추 두 줄 · ZP 폰 화면 빛 · AJ 얼굴 · AJP 전단지).

**17. `place()` 는 회전이 아니라 거울이었다 — 세 번 만에 잡았다.**

`rotation.y = -facing + π/2` 였다. three 의 로컬 +Z → 월드 `(sin θ, −cos θ)` 규약과 합치면
이건 **북축 대칭 반사**다:

| facing | 의도 | 실제 |
|---|---|---|
| 0 (동) | 동 | **서** ✗ |
| π (서) | 서 | **동** ✗ |
| ±π/2 (남·북) | 남·북 | 남·북 ✓ |

남·북은 그 반사의 **고정점**이라 멀쩡해 보인다. 내 검증은 전부 남북이었다(할아버지는 벤치가
동서로 놓여 남쪽을 보고, 추격 재현도 남쪽으로 도망쳤다) — 그래서 **두 번 "정상"이라 오판했다.**
디렉터가 *동쪽으로 달리는 화면*을 주고서야 잡혔다. 좀비폰족·역무원이 멀쩡했던 것도 같은 이유다:
둘 다 **x 축**을 걷는다.

→ `θ = facing + π/2` 로 고쳤다(`npc-rig.ts` · `player-rig.ts` 둘 다 같은 버그였다).
그리고 **`YAW_FIX` 가 전부 0 이 됐다** — GP·AJ·AJP 에 붙어 있던 π 는 리그의 전방축이 아니라
**이 반사를 가리던 보정**이었다. 리포의 리그는 전부 +z 전방이다.

**규칙**: 방향 검증은 **네 방향을 전부 본다.** 남북만 보면 반사 버그는 절대 안 걸린다
(`tests/e2e/p2.spec.ts` "리그 전방축 — 네 방향" 이 잠근다).

**18. `?obs=all` 이 안 먹은 이유는 오타가 아니라 바이트였다.**
Python 힙독으로 코드를 넣으면서 `` 가 정규식 이스케이프가 아니라 **실제 백스페이스(0x08)** 로
파일에 들어갔다. `/[?&]obs=all<BS>/` 는 영원히 불일치인데 눈으로는 멀쩡하다. `od -c` 로 잡았다.

**19. QTE 를 타이밍 바로 갈아끼웠다** (디렉터 지시).
`QteState` 에서 `dir/travel/beatMs` 를 걷고 `pos/dirSign/speedMul` 을 넣었다.
액션도 `QTE_INPUT`+`QTE_STROKE` → **`QTE_HIT` 하나**로 줄었다 — 입력이 클릭 하나라
프레임마다 상태를 밀어 넣을 이유가 없어졌다. 마커는 `ADVANCE` 가 움직인다.

바꾸면서 **`InputFrame.qteDelta` 가 죽었다.** 원본 마우스 델타를 누적하던 필드인데
드래그 판정이 사라지자 읽는 곳이 없다 — `input.ts`·`main.ts` 의 `pending` 까지 같이 걷었다.
(P1 이 "마우스 델타를 버리면 스트로크가 짧아진다"고 이월까지 만들어 둔 자리다.
 **기능을 바꿀 때는 그 기능을 위해 만든 배관도 같이 걷는다.**)

자동조종(`_pilot.ts playQte`)은 이제 **구간 중앙에 가까울 때만** 누른다 —
`pressInteract` 는 다음 tick 의 `ADVANCE` 뒤에 판정되므로 구간 경계에서 누르면
그 사이 마커가 나간다. 여유(반폭 0.07 vs 프레임당 최대 0.03)를 다 쓰지 않는다.
