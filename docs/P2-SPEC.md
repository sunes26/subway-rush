# 지하철 러쉬 — P2 기획서 (Specification)

**버전** v1.0 · **작성** 2026-08-06 · **선행** `docs/P1-SPEC.md` 완료 · **상위 문서** `docs/GDD-subway-rush.md` §10 P2

> **P2 한 줄 정의**
> **P0은 "역을 통과할 수 있다", P1은 "역에서 판단할 것이 생긴다"였다.
> P2는 "두 번째 판이 첫 번째 판과 다르다"다.**
>
> P1을 두 번 플레이하면 두 번 다 같은 일이 벌어진다. 시드가 바꾸는 것은 잔액과
> 고장 게이트 번호 둘뿐이고, 아이템은 4종이라 들고 다닐 조합이 없고, 엔딩은 6종인데
> 그중 4종이 *탑승 여부와 잔여 시간*만 본다. **리플레이가 걸릴 데가 없다.**
>
> P2는 걸릴 데를 만든다 — 시드마다 다른 방해요소 세트, 슬롯을 두고 다투는 아이템 12종,
> 그리고 **모아야 채워지는 도감 14칸.**

**각 항목이 "무엇으로 끝나면 완료인가"를 못 박는다.**

**P2 게이트 (이게 안 되면 P2가 아니다)**

> 시드를 지정하지 않고 **연속 3회** 플레이하면 세 판의 **활성 방해요소 세트가 서로 다르고**,
> 도감에 **서로 다른 엔딩 3개**가 기록되며, 브라우저를 새로 고쳐도 그 3개가 남아 있다.
> 그리고 이 전부가 헤드리스 시뮬로 재현 가능해야 한다.

## 1. 왜 이 순서인가

P1에서 배운 것: **판정 대상보다 판정의 입력을 먼저 만들면 두 번 짠다.**
(P1은 반대로 했다 — 상호작용 코어를 먼저 깔았고 그게 맞았다.)

P2의 입력은 **시드**다. 방해요소 6종·아이템 7종·엔딩 8종이 전부 "이번 판에 있는가"를
시드에 묻는다. 시드 셔플을 나중에 넣으면 **먼저 넣은 것들을 전부 다시 배선**해야 한다.

```
 S14 시드 · 세이브 ──── 이번 판이 "다른 판과 다르다"           (다른 전부의 전제)
      │
 S15 아이템 7종 ─────── 들고 다닐 것이 "슬롯보다 많다"          (선택이 비용이 되는 지점)
      │
 S16 방해요소 6종 ───── 그 아이템이 "쓸 데가 생긴다"            (아이템↔방해 짝짓기)
      │
 S17 역무원 · 비상게이트 ─ 개찰구 말고도 "문이 하나 더 있다"     (E-09·E-12 의 전제)
      │
 S18 엔딩 8종 · 도감 ─── 위 전부가 "기록으로 남는다"            ★ P2 게이트
      │
 S19 사운드 전량 ────── 보이는 것에 "들리는 것이 붙는다"
      │
 S20 미니맵 · Q · 모달 ─ P1 이 남긴 빚 3건
      │
 S21 120점 패스 ─────── 돌아가는 것을 "더 좋게"
```

거꾸로 하면 안 되는 이유:
- 시드 없이 방해요소를 넣으면 → 13종이 매판 전부 나와서 3분이 아니라 6분짜리가 된다
- 아이템 없이 방해요소를 넣으면 → 대응 수단이 없어 전부 "무조건 손해"가 된다 (GDD §11 "재미없는 실패")
- 비상게이트 없이 E-09를 넣으면 → 부정승차의 **대안**이 없어 그냥 함정이다
- 도감 없이 엔딩 14종을 넣으면 → 플레이어는 자기가 몇 개 봤는지 모른다. **엔딩이 세일즈 포인트인데 카운터가 없다**

## 2. F-P2-01 · 시드 랜덤화와 세이브

### 2.1 시드가 지금 하는 일 / 앞으로 할 일

| 대상 | P1 | P2 |
|---|---|---|
| 시작 잔액 | `BALANCE_POOL[seed % 5]` | 그대로 |
| 고장 게이트 | 6기 중 2기 | 그대로 |
| 안내 LED 힌트 | 60% 확률 | 그대로 |
| 자판기 동전액 | 합계 보장 후 분배 | 그대로 |
| **활성 방해요소** | — (전부 항상) | **12종 중 8종** ★신규 |
| **아이템 배치** | 고정 | 고정 (위치는 학습 대상이다) |
| **대기줄 정답** | ⓒ 고정 | **줄 길이 셔플** ★신규 (R3) |
| 시드 자체 | `?seed=` 없으면 `12345` | **없으면 무작위** ★신규 |

**아이템 위치는 셔플하지 않는다.** GDD §8.1의 리플레이 곡선이 *"4~6회에 효자손 체인 발견"*을
전제한다 — 위치가 매판 바뀌면 학습이 누적되지 않고 그냥 뒤지는 게임이 된다.
바뀌는 것은 **무엇이 방해하는가**지 **무엇이 어디 있는가**가 아니다.

### 2.2 R3 해소 — 대기줄

미해결 리스크 R3: *"노선도(I-13)를 주우면 Z5 대기줄 ⓒ가 항상 정답이라 판단이 사라진다."*

분리한다.
- **환승계단 위치는 고정** — 실제 역이니까 매판 바뀔 리 없다
- **줄 길이는 시드 셔플** — ⓐⓑⓒ 세 줄의 대기 인원이 시드로 정해진다

노선도는 *"어느 문이 환승계단에 가까운가"*를 알려주고(고정 정보),
줄 길이는 *"그 문 앞에 몇 명 서 있는가"*를 결정한다(가변 정보).
**둘을 곱해야 답이 나오므로 노선도가 있어도 판단이 남는다.**

### 2.3 세이브 (SYS-12)

`localStorage` 키 하나. 스키마 버전을 넣어 둔다 — 엔딩 14칸은 앞으로도 안 바뀌지만
도감 코멘터리(P3)가 붙으면 구조가 는다.

```
subway-rush.save.v1 = {
  v: 1,
  endings: { "E-01": { seen: 3, bestMs: 12400 }, ... },
  plays: 17,
}
```

**세이브 실패는 게임을 멈추지 않는다.** 사파리 프라이빗 모드는 `localStorage.setItem`이 던진다.
전부 try/catch로 감싸고 실패하면 메모리 저장소로 격하한다 — 그 판의 도감은 보이고 다음 판에 사라진다.

**모든 신규 아이템이 방해요소와 1:1 이상으로 짝지어져 있다.** 이게 P2-1과 P2-2를 연달아
하는 이유다. 짝 없는 아이템은 인벤토리 공간을 먹는 쓰레기고, 대응 없는 방해요소는 함정이다.

예외 하나 — **I-07 커피는 짝이 없다.** 스태미너 자체가 상시 압박이라 짝이 필요 없다.

### 3.2 슬롯 경제 — 이게 P2의 진짜 게임이다

슬롯은 3칸이고 점유 아이템은 11종이다. **전부 못 든다.**

| 조합 | 얻는 것 | 잃는 것 |
|---|---|---|
| 효자손 · 우산 · 커피 | 잔액 충전 + 인파 돌파 + 스태미너 | 인파 역류에 그대로 맞는다 |
| 이어폰 · 마스크 · 노선도 | 방해 3종 무시 + 미니맵 | **잔액 충전 수단이 없다** |
| 지갑 · 노선도 · 아무거나 | 비상게이트 + 최단 경로 | 시간을 역무실 왕복에 쓴다 |

**교체 모달(UI-14)이 P2에 있는 이유가 이것이다.** P1은 슬롯이 차면 0번을 말없이 떨궜다.
아이템이 4종일 땐 그래도 됐지만 11종이면 **말없이 떨구는 것이 곧 손실**이다.

### 4.2 활성화 셔플 — 8종

12종(OBS-14 단소 제외) 중 **8종**이 시드로 활성화된다. GDD §11: *"시드당 8~9종만 활성화.
나머지는 다른 회차에 등장 → 리플레이 유인으로 전환."*

**항상 켜지는 것 4종** — 이게 없으면 게임의 뼈대가 사라진다.
`OBS-01`(고장 개찰구) · `OBS-02`(잔액부족) · `OBS-11`(대기줄) · `OBS-12`(스크린도어)

**셔플 대상 8종 중 4종 선택** — `OBS-03` `OBS-04` `OBS-05` `OBS-06` `OBS-07` `OBS-08` `OBS-10` `OBS-13`

> **셔플이 3분 예산을 깨면 안 된다.** 8종 전부 켜지면 페널티 합이 −60s가 넘는다.
> 그래서 **비용 상한**을 둔다: 선택된 4종의 명목 페널티 합이 −45s를 넘으면 다시 뽑는다.
> 예산 검산은 `docs/P2-BALANCE.md`(스윕 자동 생성)가 시드 200개로 증명한다.

### 4.3 OBS-13 역무원 — 유일한 즉사

GDD §9.4: *"즉사가 허용되는 건 E-09 부정승차·E-11 에스컬레이터 참사 둘뿐 — 둘 다 명백한 고의 행동이다."*

역무원은 **개찰구를 뛰어넘었을 때만** 반응한다. 그냥 서 있는 것으로는 아무 일도 안 일어난다.
그리고 시야콘이 **보인다** — 바닥에 옅은 부채꼴. 보이지 않는 즉사는 함정이다.

> 지금 점프 정점 0.54m로는 개찰구 플랩 1.15m를 못 넘는다(P1 유닛 테스트가 잠금).
> **P2에서 이 잠금을 풀지 않는다.** 부정통과는 *비상게이트가 열린 상태에서 요금 미납으로
> 통과*하는 것으로 정의한다 — 점프 물리를 건드리지 않고 E-09를 켤 수 있다.

## 5. F-P2-04 · 역무원 · 비상게이트

개찰구(6기) 말고 **문이 하나 더** 생긴다. GDD 부록 A 시크릿 3·8번이 여기로 들어온다.

| 경로 | 조건 | 비용 | 양심 |
|---|---|---|---|
| 유실물 지갑 반납 (OBJ-13) | I-11 소지 | 반납 2.0s | **+2** |
| 인터폰 호출 (OBJ-22) | — | 대기 −15s | 0 |
| 무단 통과 | 비상게이트 열림 + 요금 미납 | 0s | **−3** → 역무원 시야면 **E-09** |

**비상게이트는 잔액을 안 본다.** 잔액 0원 시드에서 자판기를 다 긁어도 요금이 모자라는
경우가 P1 실측 60% 시드 중 일부 존재했고, P1은 자판기 합계 보장으로 막았다.
P2는 **막는 대신 문을 하나 더 준다** — GDD §11의 "충전 루트 4개"가 여기서 완성된다.

### 6.1 신규 8종

| ID | 엔딩 | 조건 | 우선 |

## 9.5 F-P2-08 · 자판기 QTE 개편 (디렉터 지시 2026-08-06)

**바꾼 것**: 마우스 좌↔우 왕복 드래그(누적 이동량 + 리듬) → **왕복 마커 + 중앙 클릭.**

| 항목 | 값 | 근거 |
|---|---|---|
| 필요 성공 | **3회** | 자판기 3대·동전 배분이 이 값에 맞물려 있다 |
| 입력 | **`E` 또는 좌클릭** | `pressInteract` 하나가 둘 다 받는다. 손이 어디 있든 누른다 |
| 왕복 주기 | **1.571초** (좌→우→좌) | 최초 1.1초에서 **속도 0.7배**로 낮췄다(플레이 확인). 구간 폭은 안 건드린다 |
| 성공 구간 | 트랙의 **14%** (반폭 0.07) | 좁히면 주사율·입력 지연이 실력을 덮는다 (GDD §11 "판정은 관대하게") |
| 난이도 | 성공마다 속도 **×1.12** · **구간은 그대로** | 좁히면 "아까 됐던 클릭이 안 되는" 억울함이 생긴다. 빨라지는 건 눈에 보인다 |
| 실패 | 미스 3 누적 → **−5s** · 6초 초과 → 실패 | P1 값 유지 |

**왜 바꿨나** — GDD §5.4 원안(드래그)은 두 가지가 걸렸다.
① 누적 이동량(px)으로 판정하니 **마우스 감도·DPI 가 난이도를 바꿨다.**
② **판정 이유가 화면에 없었다** — 왜 미스인지 안 보인다.
타이밍 바는 규칙이 게이지에 전부 그려지고 입력이 클릭 한 번이라 장비를 안 탄다.
*"마우스가 두 번째 동사"* 라는 GDD 의 의도는 유지된다 — 손목 왕복 대신 **순간 선택**이다.

**구현 규칙 두 개**
- 마커 위치는 상태(`qte.pos`)에 있고 **`ADVANCE` 에서만 움직인다.** 시스템이 또 밀면
  프레임당 두 번 움직여 판정이 프레임레이트를 탄다
- `inZone(pos)` 는 순수 함수다 — **자동조종이 계산해서 누를 수 있어야** 시드 200 스윕이 성립한다

**덤으로 지운 것**: `InputFrame.qteDelta`. 드래그 판정이 사라지면서 읽는 곳이 없어졌다.

## 9.6 F-P2-09 · 소지품 10칸 · 즉시 착용 · ESC 설정 (디렉터 지시 2026-08-06)

### (1) 슬롯 3 → **10**

GDD §5.2 는 *"3슬롯 고정 · 슬롯 압박 자체가 선택을 만든다"* 였다. 디렉터가 10칸을 지시했으므로
**압박의 자리를 옮긴다**: 판단은 이제 "무엇을 버릴까"가 아니라 **"무엇을 주우러 갈까"**다 —
아이템 11종을 다 주우려면 3분 안에 동선이 안 나온다. 압박의 원천은 슬롯이 아니라 시계다.

| 항목 | 값 | 근거 |
|---|---|---|
| 슬롯 수 | **10** | `SLOTS` 하나가 시뮬·HUD·킷을 동시에 정한다 |
| 키 | `1`~`9` + **`0`(10번)** | 숫자열 순서를 그대로 읽는다. 슬롯 수를 넘는 입력은 소비처가 무시 |
| HUD 칸 크기 | 72px → **54px** | 72px×10 이면 패널이 824px 라 스태미너·미니맵과 부딪힌다. **칸을 줄였지 개수를 안 줄였다** |
| 교체 창(UI-14) | 그대로 | 슬롯이 늘어도 "직전 동작 되돌리기"라는 성격은 안 바뀐다 |

### (2) 무선이어폰(I-05) **즉시 착용**

줍는 순간 `EARBUDS_ON` 이 켜진다. `ItemDef.autoWear` 로 표에 적고, 습득 액션이 착용 액션을
같이 낸다 — 습득과 착용이 **한 프레임**에 끝나야 "주웠는데 왜 꺼져 있지"가 안 생긴다.

- 즉시 착용은 **대가가 가벼운 착용형에만** 준다. 손이 묶이거나 시야가 막히는 것까지 자동으로
  켜지면 그건 선택이 아니라 사고다. 현재 `autoWear` 는 I-05 **하나뿐**이고 유닛 테스트가 그 수를 지킨다
- 되돌릴 수 있다 — 슬롯 키로 끄면 그대로 꺼진다(대가가 있는 착용이므로)

### (3) ESC **설정 화면** (UI-15 · SCN-09 · Figma `node 15:4`)

일시정지 겸 설정. **여는 순간 시뮬이 멈춘다** — 3분이 도는 게임에서 "설정을 보는 동안
시간이 흘렀다"는 납득이 안 된다. 멈췄다는 사실은 `PAUSED` 칩으로 화면에 적는다.

| 구역 | 항목 | 적용 대상 |
|---|---|---|
| 사운드 | 마스터 / 배경음악 / 효과음 | 마스터 아래 **버스 2개**(sfx·bgm)로 갈라 각각 잡는다 |
| 조작 | 마우스 감도(25~300%) · 상하 반전 | `FPV.sensitivity` 에 곱하는 **배율**. 절대값을 저장하면 튜닝 변경이 무시된다 |
| 그래픽 | 해상도(100/75/50%) · 화면 모드 | 렌더 **버퍼만** 줄인다(UI 는 선명한 채로 3D 만 가벼워진다) · 전체화면 |
| 푸터 | 홈으로 돌아가기 · 닫기(ESC) | 홈은 판을 새로 만들고 타이틀로 |

**ESC 우선순위** — 이미 네 곳이 ESC 를 쓴다(대화 취소·QTE 포기·교체 되돌리기·도감 닫기).
설정은 **아무도 안 쓸 때만** 가져간다. 뒤집으면 취소하려던 사람이 일시정지를 만난다.

**포인터 락에서는 ESC 키 이벤트가 페이지에 안 온다.** 브라우저가 먼저 먹어 락을 푼다(명세대로다).
그래서 "락이 풀렸다"를 ESC 신호로 읽되, 창 포커스를 잃어서 풀린 경우(`document.hasFocus()` 거짓)는
제외한다 — 안 그러면 알트탭 한 번에 게임이 멈춘 채로 돌아온다.

**기본값은 항등이다** — 볼륨 3종·감도 전부 1.0, 해상도 100%. 설정을 안 만진 사람의 게임은
예전과 **완전히 같은 소리·같은 시선**이어야 한다. 기본값이 소리를 바꾸면 그건 설정이 아니라 리믹스다.

대신 `NODE_DROP` 목록 자체가 빚이다: 다음 역 리빌드 때 노드를 지우고 목록을 비운다.

### (2) 노선도 `OBJ-15-MAP` — Z2 남쪽 벽

옛 자리(안내판 남쪽 면 26, 15.4)는 판 표면과 종이 톤이 같아 **벽 무늬로 읽혔다.**
디렉터가 준 지점 (42.5, 5.1, −6.0) 은 **사람이 서 있던 자리**라, 거기서 가장 가까운 벽면
(레이캐스트 실측 — 남쪽 `ST_WALL`, y=0, 5.1 m 앞)에 x 를 그대로 두고 붙였다.

| 항목 | 값 | 근거 |
|---|---|---|
| 위치 | (42.5, 0.06, 바닥+1.5) | 벽에서 6cm 띄워 z-fighting 회피 · 서서 읽는 게시물 높이 |
| 방향 | `faceYaw = π` | 인쇄면이 대합실(북쪽)을 본다. 기본 각이면 벽에서 45° 떠 보인다 |
| 크기 | `propScale = 7` → 0.57 m | 메시 원본은 손바닥 크기(0.082 m)다 — 그게 **주머니에 들어가는** 물건의 실치수라 벽에 그대로 붙이면 3 m 앞에서 검은 얼룩이다 |
| 밝기 | `backlit = true` | 이 역의 실광원은 0.03~0.31 이다(밝기는 라이트맵이 낸다). 무광 인쇄물은 **새까맣게 나온다**(실측). 실제 역 노선도판도 백라이트 박스다 |

세 속성(`faceYaw`·`propScale`·`backlit`)은 `Interactable` 의 **선택 필드**로 넣었다 —
게시물이라는 종류가 하나 더 생기면 같은 세 값을 쓴다. 다른 습득물은 전부 기본값이라 무변화다.
