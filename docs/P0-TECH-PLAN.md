**의도적으로 안 쓰는 것**

| 후보 | 기각 사유 |
|---|---|
| React / 상태 라이브러리 | HUD는 DOM 몇 개다. 60fps 루프에 리액트 리컨실리에이션을 끼우면 손해만 본다 |
| 물리 엔진 (Rapier/Cannon) | 맵이 전부 2m 격자 직교다. AABB 슬라이딩 30줄이면 끝난다. 물리 엔진은 WASM 400KB + 예측 불가능한 떨림 |
| ECS 프레임워크 | 엔티티가 P0 기준 12종. 오버엔지니어링 |

### 1.3 월드를 코드로 짓는 이유

Blender 씬을 그대로 내보내지 않는다. 세 가지 이유다.

1. **예산** — 1,675 오브젝트 / 1.03M 폴리곤. gzip GLB로도 30MB 급. 목표 번들 900KB의 33배.
2. **충돌** — 메시 충돌은 이 맵에 과잉이고, 좌표가 코드에 없으면 게이트 y=6/10/14/18/22/26 같은 **로직 상수를 씬에서 역추출**해야 한다. 버그의 온상.
3. **반복 속도** — 밸런싱은 좌표를 만지는 일이다. `world.ts` 한 줄 수정 vs Blender 열고 → 옮기고 → 익스포트 → 리로드.

대신 **부록 A 좌표표가 계약서**다. 코드와 Blender 씬은 같은 숫자를 본다. 아트 레퍼런스와 최종 렌더는 Blender가, 플레이는 코드가 담당한다.

캐릭터는 반대다 — `mc_character_rigged.glb`는 590KB에 애니 9종. **그대로 쓴다.**

## 3. 아키텍처 — 3계층 단방향

```
   ┌──────────────── 매 프레임 ────────────────┐
   │                                          │
   │  input.sample()  ──► InputFrame          │
   │                          │               │
   │                          ▼               │
   │   ┌─── 시뮬레이션 (고정 60Hz) ──────────┐  │
   │   │  systems.forEach(sys =>            │  │
   │   │     actions.push(...sys(state,ctx))│  │
   │   │  )                                 │  │
   │   │  state = actions.reduce(reducer,   │  │
   │   │                          state)    │  │
   │   └────────────────────────────────────┘  │
   │                          │                │
   │                          ▼                │
   │   ┌─── 렌더 (가변, 보간) ───────────────┐  │
   │   │  rigs.forEach(r => r.sync(state,α))│  │
   │   │  renderer.render(scene, camera)    │  │
   │   │  hud.sync(state)                   │  │
   │   └────────────────────────────────────┘  │
   └──────────────────────────────────────────┘
```

**철칙 3개**

1. **시스템은 상태를 직접 바꾸지 않는다.** 액션만 반환한다. → 모든 변경이 리듀서 한 곳을 통과하므로 로그·리플레이·시드 재현이 자동으로 성립한다.
2. **렌더는 상태를 읽기만 한다.** 렌더 코드가 게임플레이에 영향을 주면 프레임레이트가 밸런스를 바꾼다.
3. **시뮬은 고정 60Hz.** 프레임이 튀어도 물리가 안 튄다. 렌더는 α(보간계수)로 부드럽게 그린다.

### 3.1 고정 스텝 루프 — 정확히 이렇게

```ts
const STEP = 1000 / 60
let acc = 0, prev = performance.now()

function frame(now: number) {
  let dt = now - prev; prev = now
  if (dt > 250) dt = STEP            // 탭 복귀 스파이럴 차단 (기획서 F-04 성공기준)
  acc += dt
  let steps = 0
  while (acc >= STEP && steps++ < 5) { state = tick(state, STEP); acc -= STEP }
  render(state, acc / STEP)
  requestAnimationFrame(frame)
}
```

`dt > 250` 클램프가 **탭 백그라운드 후 복귀 시 타이머 점프**를 막는다. 이게 없으면 사용자가 탭을 5분 두고 오면 게임이 즉시 끝나 있다.

## 4. 핵심 기능 작동 방식

### 4.1 F-01 이동 — 카메라 상대 + 지수 감쇠

```
입력 (WASD) → 카메라 요 회전 적용 → 정규화 목표 방향
                                          │
    목표속도 = dir × (스프린트 ? 8.3 : 5.0) × (1 − speedPenalty)
                                          │
    vel = lerpExp(vel, 목표속도, dt, τ)     τ = 입력있음 0.12s / 없음 0.09s
                                          │
    다음위치 = pos + vel·dt  ──► collision.resolve() ──► 확정
                                          │
    facing = lerpAngle(facing, atan2(vel), 14 rad/s)
    z = ground.sample(x, y)     ← 층 · 램프 볼륨
```

`lerpExp(a,b,dt,τ) = b + (a−b)·exp(−dt/τ)` — **프레임레이트 독립** 지수 보간. 흔히 쓰는 `lerp(a,b,0.2)`는 60fps와 144fps에서 다르게 움직인다. 그건 버그다.

**스태미너**: 스프린트 −22/s, 회복 +14/s (마지막 스프린트 후 1.0s 지연). 0 도달 시 잠금, 30 회복해야 해제 (히스테리시스 — 없으면 0 근처에서 스프린트가 깜빡인다).

### 4.2 F-03 충돌 — AABB 슬라이딩

```
1. 다음 위치 후보 계산
2. 근처 AABB 질의 (16m 균일 그리드 해싱 — 브로드페이즈)
3. X축만 이동 → 겹치면 X 되돌림
4. Y축만 이동 → 겹치면 Y 되돌림
5. 확정
```

축별 분리 해결(separate-axis resolve)이 벽에 붙어 미끄러지는 느낌을 만든다. 동시 해결하면 모서리에서 끼인다.

**램프 볼륨** (경사): `{xy범위, z시작, z끝, 축}`. 볼륨 안이면 `z = lerp(z0, z1, 진행률)`. 계단·에스컬레이터·출구계단 3종.

**출처**: 모든 박스는 `data/world.ts`에서 부록 A 좌표로 선언. 예:
```ts
{ id:'OBJ-28-N', box:[44,6.6, 56,7.0], h:3.0 }      // Z2 가림막 북면
{ id:'GATE-G3',  box:[60.3,13.7, 61.7,14.3], h:1.2 } // 게이트 본체
```

### 4.3 F-05 개찰구 — 상태 기계

```
      ┌──────────┐   플레이어가 통로 진입 (x 59.8~60.3)
      │   IDLE   │──────────────┐
      └──────────┘              ▼
           ▲              ┌───────────┐
           │              │  TAGGING  │ 0.35s
           │              └─────┬─────┘
           │                    │ 판정
           │        ┌───────────┴───────────┐
           │   정상 & 잔액≥1400          그 외
           │        │                       │
           │        ▼                       ▼
           │  ┌──────────┐            ┌──────────┐
           │  │  OPEN    │ 플랩 개방   │ REJECT   │ 부저 · 적색
           │  │  2.0s    │ −1,400원   │ 3.0s CD  │ −8s · 1.6m 후퇴
           │  └────┬─────┘            └────┬─────┘
           │       │ x≥62                  │
           │       ▼                       │
           │  ┌──────────┐                 │
           │  │  PASSED  │ ★비가역          │
           │  └──────────┘                 │
           └───────────────────────────────┘
```

**시드**: `rng(seed).pick([1..6])`, 15% 확률로 2개. 램프 색은 이 결과의 **직접 투영**이다 — 별도 데이터가 아니라 `working.includes(id) ? GREEN : RED`. 램프가 거짓말할 구조적 가능성 자체를 없앤다.

**쿨다운 3.0s**가 무작위 대입을 막는다. 없으면 6개를 5초 만에 다 시도할 수 있고 그러면 이 게임의 유일한 판단이 사라진다.

### 4.4 F-07 열차 — 시간 구동 (Time-driven)

열차는 **플레이어와 무관하게** 시간만 보고 움직인다. 상태는 `elapsedMs`의 순수 함수다.

```ts
const trainAt = (t: number) =>
  t < 168_000 ? { s:'incoming', x: lerp(320, 78, ease(t/168_000)) , door:0 }
: t < 172_000 ? { s:'arriving', x: decel(t), door:0 }
: t < 180_000 ? { s:'open',     x: STOP,     door: min(1,(t-172_000)/1200) }
: t < 181_200 ? { s:'closing',  x: STOP,     door: 1-(t-180_000)/1200 }
: t < 182_000 ? { s:'closed',   x: STOP,     door:0 }
:               { s:'departed', x: lerp(78, -160, ...), door:0 }
```

순수 함수라서 **시간을 스크럽하면 열차가 그대로 따라온다** → 디버그에서 t=179s로 점프해 탑승 판정만 반복 테스트할 수 있다. E2E 테스트 시간이 3분에서 3초로 줄어든다.

**탑승 판정**: 문 32개소를 `x = 78 + 16k + {2,6,10,14}`로 생성. 매 틱 플레이어와 가장 가까운 문 1개만 검사(선형 탐색 32회는 무시할 비용). 조건 3개(문 상태 · 개구 사각형 내부 · +y 입력)가 전부 참이면 `BOARD` 액션.

### 4.5 F-02 카메라 — 존 프리셋 보간

```
zone 변경 감지 → 목표 {yaw, pitch, dist} = PRESET[zone]
              → 1.2s ease-in-out 보간 (컷 없음)

매 프레임:
  anchor = player.pos + vel × 0.28          선행(look-ahead)
  target = lerpExp(target, anchor, dt, 1/6.0)
  camera.pos = target + sph(yaw+userYaw, pitch+userPitch, dist×userZoom)
  camera.lookAt(target + [0,0,0.9])
```

**Z3 특례**: 프리셋 대신 `dist`를 계산한다 — y 6~26(20m)이 화면 세로 70%에 들어가는 거리. `dist = 10 / (2·tan(fov/2)·0.7) × aspectCorr`. 기획서 F-02 성공기준(램프 6개 동시 가시)을 코드로 보장한다.

### 4.6 렌더 — 툰 + 인스턴싱

- **툰**: `MeshToonMaterial` + 3단 그라디언트 램프 텍스처(4×1 DataTexture). 조명 1 directional + 1 hemisphere.
- **아웃라인**: 후면 확장(back-face expansion) — 동일 지오메트리를 `BackSide`, 법선 방향 팽창 셰이더로 한 번 더. 드로우 콜 2배지만 인스턴싱으로 상쇄.
- **인스턴싱**: 반복 오브젝트(기둥 8, 게이트 6, 안전문 32, 계단 87단, 역명판 8, 전차 8량)는 전부 `InstancedMesh`. 87단 계단을 개별 메시로 그리면 그것만으로 드로우 콜 예산을 절반 먹는다.
- **안개**: B1/B2 `FogExp2` — 존 밖 지오메트리를 자연스럽게 잘라 프러스텀 컬링을 돕고, 지하 분위기도 같이 얻는다.

## 6. 테스트 전략

### 6.1 계층

| 계층 | 도구 | 대상 | 비율 |
|---|---|---|---|
| 유닛 | Vitest | 리듀서 · 시스템 · 시드 · 좌표 | 70% |

| E2E | Playwright | 완주 · 성능 · 콘솔 · 스크린샷 | 10% |

### 6.2 헤드리스 시뮬 — 이 프로젝트의 핵심 테스트 장치

시스템이 순수 함수라서 **렌더 없이 게임 전체를 돌릴 수 있다.**

```ts
const sim = (seed: number, script: InputFrame[]) =>
  script.reduce((s, input) => tick(s, 16.67, input), initialState(seed))
```

이걸로 가능해지는 것:
- 3분 플레이를 **20ms에** 시뮬레이션 → 시드 1,000개 밸런싱 스윕이 20초
- 랜덤 입력 퍼즈로 소프트락 탐지 (A-5)
- 열차 스케줄을 t=179s로 점프해 탑승 판정만 반복 (§4.4)

**렌더를 순수 시뮬에서 분리한 진짜 이유가 이것이다.** 아키텍처 철칙 2는 미학이 아니라 테스트 속도다.

### 6.3 자동 검증 명령

```bash
npm test          # 유닛 + 통합
npm run test:e2e  # Playwright
npm run verify    # tsc --noEmit && test && build && test:e2e   ← 각 단계 종료 시
```

| # | 지점 | 문제 | 조치 |
|---|---|---|---|
| 1 | MAP 부록 A · 게이트 통로 0.55m | 플레이어 지름(0.64m)보다 **좁아 정상 게이트조차 통과 불가**. 시드 50개 중 6개만 통과했고 그 6개는 전부 G6(0.9m 우대용)였다 | 시각 폭 0.55m는 고증대로 유지, **충돌 개구만 ±0.4m로 확장** + 게이트 퍼널(중앙 흡착)로 시각적 관통 방지 |
| 2 | MAP 부록 A · 쉘터(−58, 23.4~25.4) | **스폰 지점(−58,24)이 쉘터 솔리드 내부**. 카메라가 벽 속에서 시작 | 쉘터를 지붕 + 기둥 4개로 분해. 버스에서 내려 쉘터 아래 선 그림이 오히려 맞다 |
| 3 | 층 겹침 (Z1/Z2, Z4/Z5) | x가 겹치는 구간에서 지면 샘플링이 다른 층을 집어 순간이동 | `sampleGround`가 **현재 고도 이하 중 가장 높은 면**을 고르도록. 층 판정은 x가 아니라 (x, z) |
| 4 | 탑승 조건 "+y 입력 유지" | 입력축은 카메라 상대라 존마다 W의 월드 방향이 다르다. Z5에서 W를 눌러도 탑승 판정이 안 섰다 | 조건을 **월드 속도 `vel.y ≥ 0.4`** 로 변경. 카메라 프리셋을 바꿔도 안 깨진다 |
| 5 | 쿼터뷰 + 외벽 4~5m | 카메라는 반드시 방 **밖 위쪽**에 선다 → 외벽이 화면 절반을 먹는다 | `Solid.renderH` 도입 — 충돌은 4~5m, 그림은 2.4m. 여기에 레이캐스트 차폐 당김 추가 |
| 6 | 움직이는 `InstancedMesh` | 열차 바운딩 스피어가 스폰 위치(x=330)로 캐시돼 정차 후 **통째로 컬링됨** | 이동하는 인스턴스는 `frustumCulled = false`. 회귀 방지 어서션 추가 |

> 5번과 6번은 문서 결함이 아니라 **3D로 옮기면서 새로 생긴 문제**다. 2D 탑다운이었으면 둘 다 존재하지 않았다.
> 이게 R-01(Three.js 전환)의 실제 비용이었고, 대가로 리깅 에셋 4종을 그대로 썼다.
